# 实体解析审核指南

## 📋 概述

本指南详细说明从原始数据到最终映射的完整流程，分为三个步骤：

1. **第一步（确定性）**：从 raw data 生成 cleaned_data.csv
2. **第二步（不确定性）**：从 cleaned_data 生成 review_files（自动审核）
3. **第三步（确定性）**：从 review_files 生成 mapping.json

## 🔄 完整工作流程

### 流程图

```
原始数据 (data/raw/*/data.csv)
    ↓
[第一步] step1_generate_cleaned_data.py（自包含脚本，包含所有工具函数）
    ↓
cleaned_data.csv (data/processed/cleaned/{benchmark_id}/cleaned_data.csv)
    ↓
[第二步] step2_generate_review_files.py（自包含脚本，包含模型解析和匹配器）
    ├─ 自动生成 model_extraction/lmarena_models.json（如果不存在）
    └─ 从 cleaned_data.csv 解析模型信息并匹配
    ↓
review_files (data/processed/review_files/{benchmark_id}_review.json)
    ↓
[人类审核] 手动编辑 review_files（修改 untrusted 和 selected_lmarena_model）
    ↓
[第三步] step3_generate_mapping.py（自包含脚本）
    ↓
mapping.json (data/processed/cleaned/{benchmark_id}/mapping.json)
```

## 第一步：生成 Cleaned Data（确定性）

### 1.1 功能说明

从原始数据 CSV 文件中提取模型名称、分数，计算排名，生成标准化的 `cleaned_data.csv` 文件。

**输入**：`data/raw/*/data.csv`（所有原始数据文件）

**输出**：`data/processed/cleaned/{benchmark_id}/cleaned_data.csv`

### 1.2 脚本位置

**脚本**：`src/processing/step1_generate_cleaned_data.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/step1_generate_cleaned_data.py
```

### 1.3 处理逻辑

脚本包含所有必要的工具函数，无需导入其他模块即可运行。

1. **遍历所有原始数据**：从 `data/raw/` 目录读取所有 `data.csv` 文件
2. **识别列名**：
   - 模型名称列：自动识别 "Model", "model", "Model Name", "AI System", "model_name", "name", "Agent" 等
   - 分数列：根据 benchmark 类型自动识别（如 "Score", "Intelligence AA-LCR", "score_value", "Numerical_Result", "accuracy" 等）
3. **提取数据**：
   - 从 CSV 中提取模型名称和分数
   - 如果存在 `model_extraction` JSON 文件，只保留其中存在的模型（确保一致性）
   - 如果不存在，使用 CSV 中的所有模型
4. **处理分数格式**：
   - 移除 ± 误差部分（如 "1490 ±6" → 1490.0）
   - 处理百分比格式（如 "71%" → 71.0）
   - 处理小数格式（如 "0.945" → 0.945）
   - 转换为浮点数用于排名计算
5. **计算排名**：
   - 按分数从大到小排序
   - 同分并列：相同分数的模型获得相同排名
   - 下一个排名跳过并列数量（如分数 [99, 98, 98, 97] → 排名 [1, 2, 2, 4]）

### 1.4 输出文件

**输出目录**：`data/processed/cleaned/{benchmark_id}/`

**文件格式**：`cleaned_data.csv`

包含三列：
- `model_name`：模型名称（与原始 CSV 中的名称完全一致）
- `score`：分数（浮点数）
- `rank`：排名（整数，同分并列）

**示例**：
```csv
model_name,score,rank
GPT-5 (high),76.0,1
GPT-5.1 (high),75.0,2
Claude Opus 4.5,74.0,3
KAT-Coder-Pro V1,74.0,3
GPT-5.2 (xhigh),73.0,5
```

### 1.5 注意事项

- 脚本会自动处理多种编码（UTF-8, GBK, Latin-1, CP1252）
- 如果找不到 `model_extraction` 文件，会使用 CSV 中的所有模型（不进行一致性验证）
- 每个 benchmark 对应一个独立的文件夹和 `cleaned_data.csv` 文件

## 第二步：生成 Review Files（不确定性）

### 2.1 功能说明

从 `cleaned_data.csv` 读取模型名称，解析模型信息，匹配 LMArena 候选，自动选择最佳匹配，生成 `review_files`。

**输入**：
- `data/processed/cleaned/{benchmark_id}/cleaned_data.csv`
- `data/raw/lmarena/Overall/data.csv`（LMArena raw data，用于生成 extraction 文件）

**输出**：`data/processed/review_files/{benchmark_id}_review.json`

**注意**：
- LMArena 的 benchmark 会被跳过（因为 LMArena 内部肯定可以匹配）
- 脚本会自动从 LMArena raw data 生成 `lmarena_models.json`（如果不存在）
- 其他 benchmark 不需要单独的 extraction 文件，直接从 `cleaned_data.csv` 读取模型名称并解析

### 2.2 脚本位置

**脚本**：`src/processing/step2_generate_review_files.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/step2_generate_review_files.py
```

### 2.3 处理逻辑

脚本包含所有必要的工具函数（模型解析、匹配器等），无需导入其他模块即可运行。

1. **生成或加载 LMArena 模型信息**：
   - 如果 `model_extraction/lmarena_models.json` 不存在，从 `data/raw/lmarena/Overall/data.csv` 自动生成
   - 只保留 Score >= 1330 的模型（Study Universe）
   - 如果文件已存在，直接加载
2. **读取模型名称**：从 `cleaned_data.csv` 读取所有模型名称
3. **解析模型信息**：使用内置的模型解析函数解析每个模型名称，提取：
   - `family`（家族）
   - `subfamily`（子家族）
   - `version`（版本）
   - `date`（日期）
   - `parameters`（参数量）
   - `other_info`（其他信息）
4. **匹配候选**：使用结构化匹配算法为每个 benchmark 模型找到所有可能的 LMArena 候选：
   - 家族、子家族、版本号必须完全一致
   - 参数量如果都有且不一致，则排除匹配
   - 日期不参与筛选
5. **自动选择最佳匹配**：
   - 单个候选且不是 NO_MATCH_FOUND：直接使用
   - 多个候选：使用相似度算法选择最佳匹配（考虑 other_info、日期、参数量、子家族）
   - 无候选或只有 NO_MATCH_FOUND：设为 `0`
6. **生成 review_file**：包含所有模型的结构化信息和候选列表

### 2.4 输出文件

**输出目录**：`data/processed/review_files/`

**文件格式**：`{benchmark_id}_review.json`

**文件结构**：
```json
{
  "GPT-5.2 (xhigh)": {
    "benchmark_info": {
      "family": "gpt",
      "subfamily": null,
      "version": "5.2",
      "date": null,
      "parameters": null,
      "other_info": ["5.2", "xhigh"]
    },
    "candidates": [
      {
        "lmarena_model": "gpt-5.2",
        "family": "gpt",
        "subfamily": null,
        "version": "5.2",
        "date": null,
        "parameters": null,
        "other_info": ["5.2"]
      }
    ],
    "untrusted": 1,
    "selected_lmarena_model": "gpt-5.2"
  },
  "o3": {
    "benchmark_info": {
      "family": "gpt",
      "subfamily": "o3",
      "version": "3.0",
      "date": null,
      "parameters": null,
      "other_info": null
    },
    "candidates": [
      {
        "lmarena_model": "o3-2025-04-16",
        "family": "gpt",
        "subfamily": "o3",
        "version": "3.0",
        "date": "2025-04-16",
        "parameters": null,
        "other_info": null
      },
      {
        "lmarena_model": "o3-mini-high",
        "family": "gpt",
        "subfamily": "o3",
        "version": "3.0",
        "date": null,
        "parameters": null,
        "other_info": ["mini", "high"]
      }
    ],
    "untrusted": 1,
    "selected_lmarena_model": "o3-2025-04-16"
  }
}
```

### 2.5 字段说明

**`benchmark_info`**：
- 从模型名称解析出的结构化信息（家族、子家族、版本、日期、参数量、其他信息）

**`candidates`**：
- 所有可能匹配的 LMArena 模型列表
- 如果没有候选，包含一个 `{"lmarena_model": "NO_MATCH_FOUND"}` 条目

**`untrusted`**：
- **默认值**：`1`（表示由 agent 完成，不可信）
- **人工审核后**：改为 `0`（表示数据严谨，但不影响后续生成）
- **注意**：后续代码不会读取这个字段，它仅用于标记数据的严谨性

**`selected_lmarena_model`**：
- **模型名称（字符串）**：自动选择或唯一候选的 LMArena 模型名称
- `0`：自动判断无对应模型
- `-1`：人类审核确认无对应模型（需人工设置）

### 2.6 特殊处理

**LMArena 跳过**：
- 所有 `lmarena_*` 的 benchmark 会被自动跳过
- 因为 LMArena 内部肯定可以匹配，不需要生成 review_file

**Artificial Analysis**：
- 10 个 benchmark 各自有独立的 review_file
- 每个 benchmark 的模型列表来自各自的 `cleaned_data.csv`

## 第三步：人类审核（手动步骤）

### 3.1 审核文件位置

**审核文件目录**：`data/processed/review_files/`

**文件格式**：JSON（`.json` 扩展名）

### 3.2 如何识别需要审核的条目

**方法1：使用 `untrusted` 字段**
- 在 JSON 文件中搜索：`"untrusted": 1`
- 这些条目都是由 agent 自动审核的，需要人工确认

**方法2：检查 `selected_lmarena_model`**
- `selected_lmarena_model: 0` 表示自动判断无匹配，需要确认
- `selected_lmarena_model` 为字符串但 `untrusted: 1` 表示自动选择，需要确认

### 3.3 审核步骤

#### 步骤 3.3.1：打开审核文件

使用以下工具之一打开 JSON 文件：
- **VS Code**（推荐）：自动格式化，语法高亮，JSON 验证
- **Notepad++**：轻量级编辑器
- **在线 JSON 查看器**：如 https://jsonviewer.stack.hu/

#### 步骤 3.3.2：审核每个模型

对于每个模型条目：

**情况1：`untrusted: 1` 且有多个候选**

示例：
```json
{
  "o3": {
    "benchmark_info": {...},
    "candidates": [
      {"lmarena_model": "o3-2025-04-16", ...},
      {"lmarena_model": "o3-mini-high", ...},
      {"lmarena_model": "o3-mini", ...}
    ],
    "untrusted": 1,
    "selected_lmarena_model": "o3-2025-04-16"
  }
}
```

**操作**：
1. 检查 `selected_lmarena_model` 的值是否正确
2. 如果不正确，修改为正确的候选模型名称
3. 如果确认正确，将 `untrusted` 改为 `0`
4. 如果确认无匹配，将 `selected_lmarena_model` 改为 `-1`，`untrusted` 改为 `0`

**情况2：`untrusted: 1` 但只有一个候选**

示例：
```json
{
  "GPT-5.2 (xhigh)": {
    "benchmark_info": {...},
    "candidates": [
      {"lmarena_model": "gpt-5.2", ...}
    ],
    "untrusted": 1,
    "selected_lmarena_model": "gpt-5.2"
  }
}
```

**操作**：
1. 检查自动选择的结果是否正确
2. 如果正确，将 `untrusted` 改为 `0`
3. 如果不正确，修改 `selected_lmarena_model` 为正确的值，然后设置 `untrusted: 0`

**情况3：`selected_lmarena_model: 0`（无匹配）**

示例：
```json
{
  "Gemini 3 Pro Preview (high)": {
    "benchmark_info": {...},
    "candidates": [
      {"lmarena_model": "NO_MATCH_FOUND"}
    ],
    "untrusted": 1,
    "selected_lmarena_model": 0
  }
}
```

**操作**：
1. 检查是否真的没有匹配的模型
2. 如果确实没有，将 `selected_lmarena_model` 改为 `-1`，`untrusted` 改为 `0`
3. 如果有但算法未找到，手动添加候选到 `candidates` 数组，然后修改 `selected_lmarena_model`

#### 步骤 3.3.3：保存修改

- 确保 JSON 格式有效（VS Code 会自动检测）
- 保存文件（Ctrl+S）

### 3.4 审核检查清单

对于每个模型，检查：

- [ ] `selected_lmarena_model` 的值是否正确
- [ ] 如果正确，`untrusted` 是否已设为 `0`
- [ ] 如果无匹配，`selected_lmarena_model` 是否为 `-1`，`untrusted` 是否为 `0`
- [ ] JSON 格式是否正确（无语法错误）

### 3.5 特殊处理：artificial_analysis

**重要**：`artificial_analysis` 的 10 个 benchmark 各自有独立的 review_file：
- `artificial_analysis_aa_lcr_review.json`
- `artificial_analysis_aime_2025_review.json`
- `artificial_analysis_gpqa_diamond_review.json`
- `artificial_analysis_humanitys_last_exam_review.json`
- `artificial_analysis_ifbench_review.json`
- `artificial_analysis_live_code_bench_review.json`
- `artificial_analysis_mmlu_pro_review.json`
- `artificial_analysis_scicode_review.json`
- `artificial_analysis_tau_bench_telecom_review.json`
- `artificial_analysis_terminal_bench_hard_review.json`

**需要分别审核每个文件**。

## 第四步：生成 Mapping.json（确定性）

### 4.1 功能说明

从 `review_files` 读取审核结果，提取 `selected_lmarena_model` 字段，生成每个 benchmark 的 `mapping.json` 文件。

**输入**：`data/processed/review_files/{benchmark_id}_review.json`

**输出**：`data/processed/cleaned/{benchmark_id}/mapping.json`

**注意**：脚本是自包含的，包含所有必要的工具函数，无需导入其他模块即可运行。

### 4.2 脚本位置

**脚本**：`src/processing/step3_generate_mapping.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/step3_generate_mapping.py
```

### 4.3 处理逻辑

脚本包含所有必要的工具函数，无需导入其他模块即可运行。

1. **读取所有 review_files**：从 `data/processed/review_files/` 读取所有 `*_review.json` 文件
2. **提取最终映射**：
   - 对于每个模型，读取 `selected_lmarena_model` 字段
   - 如果值为模型名称（字符串），则创建映射
   - 如果值为 `0` 或 `-1`，则跳过（不创建映射）
3. **去重处理**：如果多个 benchmark 模型映射到同一个 LMArena 模型，只保留第一个映射（后续重复会被自动跳过）
4. **生成 mapping.json**：将映射写入 `cleaned/{benchmark_id}/mapping.json`

### 4.4 输出文件

**输出文件**：`data/processed/cleaned/{benchmark_id}/mapping.json`

**文件格式**：
```json
{
  "GPT-5.2 (xhigh)": "gpt-5.2",
  "Gemini 3 Flash": "gemini-3-flash",
  "o3": "o3-2025-04-16",
  "DeepSeek V3.2": "deepseek-v3.2",
  ...
}
```

**重要特性**：
- 只包含有效的映射（`selected_lmarena_model` 为字符串）
- 每个 LMArena 模型在该 benchmark 中最多出现一次（重复映射会被自动去除，只保留第一个）
- 模型名称与 `cleaned_data.csv` 中的命名完全一致

### 4.5 注意事项

- 只有 `selected_lmarena_model` 为模型名称（字符串）的条目才会被添加到映射表
- `selected_lmarena_model` 为 `0` 或 `-1` 的条目会被跳过
- `untrusted` 字段不会被读取，不影响映射生成

## ❓ 常见问题

### Q1: 如何知道哪些条目需要审核？

**A**: 搜索 `"untrusted": 1` 或检查所有 `untrusted: 1` 的条目。

### Q2: `untrusted` 字段的作用是什么？

**A**: `untrusted` 字段用于标记数据的严谨性：
- `1`：由 agent 自动审核，不可信
- `0`：经过人类审核，可信

**注意**：这个字段不影响后续的映射生成，仅用于标记数据的严谨性。

### Q3: `selected_lmarena_model` 为 `0` 是什么意思？

**A**: `0` 表示系统自动判断没有对应的 LMArena 模型。如果人类确认确实没有，应改为 `-1` 并设置 `untrusted: 0`。

### Q4: `selected_lmarena_model` 为 `-1` 是什么意思？

**A**: `-1` 表示人类审核确认确实没有对应的 LMArena 模型（Score >= 1330）。这需要人工设置。

### Q5: 为什么删除了 `needs_review` 字段？

**A**: 因为我们已经认定由脚本审核的结果都是不可信的（甚至包括没有 candidates 的部分），准备对所有进行重新审核。所有 `untrusted: 1` 的条目都需要人工审核。

### Q6: 为什么删除了 `human_approved` 字段？

**A**: 改为使用 `untrusted` 字段，语义更清晰：
- `untrusted: 1` = 不可信（agent 完成）
- `untrusted: 0` = 可信（人类审核）

### Q7: 为什么 LMArena 的 benchmark 不生成 review_file？

**A**: 因为 LMArena 内部肯定可以匹配（模型名称一致），不需要生成 review_file。

### Q8: artificial_analysis 的映射如何应用？

**A**: 每个 benchmark 有独立的 review_file，审核完成后，运行 `step3_generate_mapping.py`，脚本会自动为每个 benchmark 生成独立的 `mapping.json`。

### Q9: 如果检测到重复映射怎么办？

**A**: `step3_generate_mapping.py` 会自动处理重复映射：
- 如果多个 benchmark 模型映射到同一个 LMArena 模型，只保留第一个映射
