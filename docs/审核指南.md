# 实体解析审核指南

## 📋 概述

本指南详细说明从原始数据到最终映射的完整流程，包括：
1. **从 raw data 提取模型信息** → 生成结构化 JSON 文件
2. **生成待审核文件** → 为每个模型找到候选匹配
3. **自动审核** → 系统自动选择最佳匹配
4. **人类审批** → 人工确认和修正自动审核结果
5. **应用审核结果** → 生成全局映射表
6. **生成 Cleaned 数据** → 提取分数、计算排名，生成每个 benchmark 的清理数据和映射文件

## 🔄 完整工作流程

### 流程图

```
原始数据 (data/raw)
    ↓
[步骤1] 提取模型信息 (model_extraction)
    ↓
结构化 JSON 文件 (data/processed/model_extraction/*_models.json)
    ↓
[步骤2] 生成待审核文件 (generate_review_files_v2.py)
    ↓
待审核文件 (data/processed/entity_resolution/review_files_v2/*_review.json)
    ↓
[步骤3] 自动审核 (auto_review_models.py)
    ↓
自动审核文件 (data/processed/entity_resolution/reviewed_files/*_review.json)
    ↓
[步骤4] 人类审批 (手动编辑)
    ↓
[步骤5] 应用审核结果 (apply_review_results_v2.py)
    ↓
全局映射表 (config/mapping.json)
    ↓
[步骤6] 生成 Cleaned 数据 (generate_cleaned_data.py)
    ↓
Cleaned 数据文件 (data/processed/cleaned/{benchmark_id}/)
    ├── cleaned_data.csv (模型名称、分数、排名)
    └── mapping.json (每个 benchmark 的映射表)
```

## 步骤1：从 Raw Data 提取模型信息

### 1.1 数据来源

所有原始数据位于：
```
data/raw/
├── artificial_analysis/
│   ├── aa_lcr/data.csv
│   ├── aime_2025/data.csv
│   └── ...
├── lmarena/
│   └── Overall/data.csv
├── selenium/
│   ├── humaneval/data.csv
│   └── ...
└── ...
```

### 1.2 提取过程

**脚本位置**：`src/processing/temp_extraction_scripts/extract_all_benchmarks.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/temp_extraction_scripts/extract_all_benchmarks.py
```

**处理逻辑**：
1. 遍历 `data/raw/` 目录下的所有 `data.csv` 文件
2. 从每个 CSV 文件中提取模型名称
3. 解析模型名称，提取结构化信息：
   - `family`（家族）：如 gpt, gemini, claude
   - `subfamily`（子家族）：如 gpt-5, gemini-pro（pro/preview/flash/heavy/r1 等作为后缀）
   - `version`（版本）：统一为浮点数格式（如 3.0，v3 和 3.0 视为相同）
   - `date`（日期）：保持原格式（dec, 2412, 1205 等，不做处理）
   - `parameters`（参数量）：只匹配 20B, 1B 格式，排除 thinking-32k 和 A2B
   - `other_info`（其他信息）：剩余的所有信息
4. 对于 LMArena Overall：只保留 Score >= 1330 的模型
5. 对于 Artificial Analysis：10 个 benchmark 共享同一个模型列表

### 1.3 输出文件

**输出目录**：`data/processed/model_extraction/`

**文件格式**：每个 benchmark 对应一个 JSON 文件
- `lmarena_models.json` - 126 个模型（Score >= 1330）
- `artificial_analysis_models.json` - 317 个模型（10 个 benchmark 共享）
- `{method}_{benchmark_name}_models.json` - 其他 benchmark

**文件结构示例**：
```json
{
  "gemini-3-pro": {
    "family": "gemini",
    "subfamily": "gemini-pro",
    "version": "3.0",
    "date": null,
    "parameters": null,
    "other_info": null
  },
  "GPT-5.2 (xhigh)": {
    "family": "gpt",
    "subfamily": null,
    "version": "5.2",
    "date": null,
    "parameters": null,
    "other_info": ["5.2", "xhigh"]
  }
}
```

### 1.4 特殊处理

**组织名和模型名连在一起**：
- `Anthropicclaude-opus-4-5` → 识别为 `claude` 家族
- `MoonshotAIkimi-k2-0905` → 识别为 `kimi` 家族

**带前缀的模型名**：
- `google/gemini-3-pro-preview` → 移除前缀，识别为 `gemini` 家族
- `openai/gpt-5.2-2025-12-11` → 移除前缀，识别为 `gpt` 家族

**斜杠分隔的参数量变体**：
- `Qwen3-Coder 480B/A35B` → 取第一部分，识别为 `qwen` 家族

**特殊模型系列**：
- `Magistral` → `mistral` 家族
- `Devstral` → `mistral` 家族
- `Terminus` → `deepseek` 家族
- `Hermes` → `llama` 家族
- `o1`, `o3`, `o4`, `o5` → `gpt` 家族

## 步骤2：生成待审核文件

### 2.1 脚本位置

**脚本**：`src/processing/generate_review_files_v2.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/generate_review_files_v2.py
```

### 2.2 处理逻辑

1. **加载 LMArena 模型信息**：从 `data/processed/model_extraction/lmarena_models.json` 读取
2. **遍历所有 benchmark**：从 `data/processed/model_extraction/` 读取所有 `*_models.json` 文件
3. **为每个 benchmark 模型找候选匹配**：
   - 使用结构化匹配算法
   - 匹配规则：
     - ✅ `family`（家族）必须完全一致
     - ✅ `subfamily`（子家族）必须完全一致（如果都有）
     - ✅ `version`（版本号）必须一致（标准化后：3 和 3.0 视为相同）
     - ⚠️ `parameters`（参数量）如果都有且不一致，则排除匹配
     - ❌ `date`（日期）不参与筛选
     - ❌ `other_info`（其他信息）不影响匹配
4. **生成 JSON 文件**：每个 benchmark 一个审核文件

### 2.3 输出文件

**输出目录**：`data/processed/entity_resolution/review_files_v2/`

**文件列表**：共 21 个文件
- `artificial_analysis_review.json` - 317 个模型（会应用到所有 10 个 benchmark）
- `lmarena_review.json` - 126 个模型
- `{method}_{benchmark_name}_review.json` - 其他 benchmark

**文件结构示例**：
```json
{
  "GPT-5.2 (xhigh)": {
    "benchmark_info": {
      "family": "gpt",
      "subfamily": null,
      "version": "5.2",
      "date": null,
      "parameters": null,
      "other_info": ["5.2", "xhigh"]
    },
    "candidates": [
      {
        "lmarena_model": "gpt-5.2",
        "family": "gpt",
        "subfamily": null,
        "version": "5.2",
        "date": null,
        "parameters": null,
        "other_info": ["5.2"]
      }
    ]
  },
  "Gemini 3 Pro Preview (high)": {
    "benchmark_info": {
      "family": "gemini",
      "subfamily": "gemini-pro-preview",
      "version": "3.0",
      "date": null,
      "parameters": null,
      "other_info": ["high"]
    },
    "candidates": [
      {
        "lmarena_model": "NO_MATCH_FOUND"
      }
    ]
  }
}
```

### 2.4 匹配规则详解

**可以匹配的条件**：
- ✅ 家族、子家族、版本号完全一致
- ✅ 参数量：如果两个都有且一致 → 可以匹配；如果只有一个有 → 可以匹配；如果两个都没有 → 可以匹配

**不能匹配的条件**：
- ❌ 家族不一致：如 GPT vs Gemini
- ❌ 子家族不一致：如 gpt-5 vs gpt-4
- ❌ 版本号不一致（标准化后）：如 5.1 vs 5.2
- ❌ 参数量不一致（如果两个都有）：如 32B vs 72B

**不影响匹配的信息**：
- ⚠️ 日期：不参与筛选
- ⚠️ other_info：不影响匹配

## 步骤3：自动审核

### 3.1 脚本位置

**脚本**：`src/processing/auto_review_models.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/auto_review_models.py
```

### 3.2 处理逻辑

1. **读取待审核文件**：从 `data/processed/entity_resolution/review_files_v2/` 读取所有 `*_review.json` 文件
2. **为每个条目添加两个新字段**：
   - `human_approved`：0（初始值，1 表示人类已认可）
   - `selected_lmarena_model`：选中的 LMArena 模型名称
   - `needs_review`：是否需要人工审核（true/false）
3. **自动选择逻辑**：
   - **单个候选且不是 NO_MATCH_FOUND**：直接使用该模型名
   - **多个候选**：根据相似度算法选择最佳匹配
   - **无候选或只有 NO_MATCH_FOUND**：设为 `0`
4. **相似度算法**（用于多候选选择）：
   - `other_info` 相似度（50% 权重）：使用 Jaccard 相似度
   - 日期匹配（20% 权重）：完全匹配得满分，年份相同得部分分
   - 参数量匹配（20% 权重）：完全匹配得满分
   - 子家族匹配（10% 权重）：完全匹配得满分，包含关系得部分分
5. **标记需要审核的情况**：
   - 有多个有效候选（即使自动选择了，也需要人工确认）
   - 相似度太低或无法确定最佳匹配

### 3.4 字段说明

**`human_approved`**：
- `0`：初始值，表示尚未被人类认可
- `1`：人类已认可该审核结果

**`selected_lmarena_model`**：
- **模型名称（字符串）**：自动选择或唯一候选的 LMArena 模型名称
- `0`：自动判断无对应模型
- `-1`：人类审核确认无对应模型（需人工设置）

**`needs_review`**：
- `true`：需要人工审核（有多个候选或置信度较低）
- `false`：不需要人工审核（已自动处理）

## 步骤4：人类审批

### 4.1 审核文件位置

**审核文件目录**：`data/processed/entity_resolution/reviewed_files/`

**文件格式**：JSON（`.json` 扩展名）

### 4.2 如何识别需要审核的条目

**方法1：使用 `needs_review` 字段**
- 在 JSON 文件中搜索：`"needs_review": true`
- 这些条目有多个候选或置信度较低，需要人工确认

**方法2：使用脚本查找**
```bash
cd Human-SIG
python src/processing/list_needs_review.py
```

**方法3：检查 `human_approved` 字段**
- `"human_approved": 0` 表示尚未被人类认可
- 即使 `needs_review: false`，也应该检查自动选择的结果是否正确

### 4.3 审核步骤

#### 步骤 4.3.1：打开审核文件

使用以下工具之一打开 JSON 文件：
- **VS Code**（推荐）：自动格式化，语法高亮，JSON 验证
- **Notepad++**：轻量级编辑器
- **在线 JSON 查看器**：如 https://jsonviewer.stack.hu/

#### 步骤 4.3.2：审核每个模型

对于每个模型条目：

**情况1：`needs_review: true` 且有多个候选**

示例：
```json
{
  "o3": {
    "benchmark_info": {...},
    "candidates": [
      {"lmarena_model": "o3-2025-04-16", ...},
      {"lmarena_model": "o3-mini-high", ...},
      {"lmarena_model": "o3-mini", ...}
    ],
    "human_approved": 0,
    "selected_lmarena_model": "o3-2025-04-16",
    "needs_review": true
  }
}
```

**操作**：
1. 检查 `selected_lmarena_model` 的值是否正确
2. 如果不正确，修改为正确的候选模型名称
3. 如果确认正确，将 `human_approved` 改为 `1`
4. 如果确认无匹配，将 `selected_lmarena_model` 改为 `-1`，`human_approved` 改为 `1`

**情况2：`needs_review: false` 但需要确认**

示例：
```json
{
  "GPT-5.2 (xhigh)": {
    "benchmark_info": {...},
    "candidates": [
      {"lmarena_model": "gpt-5.2", ...}
    ],
    "human_approved": 0,
    "selected_lmarena_model": "gpt-5.2",
    "needs_review": false
  }
}
```

**操作**：
1. 检查自动选择的结果是否正确
2. 如果正确，将 `human_approved` 改为 `1`
3. 如果不正确，修改 `selected_lmarena_model` 为正确的值，然后设置 `human_approved: 1`

**情况3：`selected_lmarena_model: 0`（无匹配）**

示例：
```json
{
  "Gemini 3 Pro Preview (high)": {
    "benchmark_info": {...},
    "candidates": [
      {"lmarena_model": "NO_MATCH_FOUND"}
    ],
    "human_approved": 0,
    "selected_lmarena_model": 0,
    "needs_review": false
  }
}
```

**操作**：
1. 检查是否真的没有匹配的模型
2. 如果确实没有，将 `selected_lmarena_model` 改为 `-1`，`human_approved` 改为 `1`
3. 如果有但算法未找到，手动添加候选到 `candidates` 数组，然后修改 `selected_lmarena_model`

#### 步骤 4.3.3：保存修改

- 确保 JSON 格式有效（VS Code 会自动检测）
- 保存文件（Ctrl+S）

### 4.4 审核检查清单

对于每个模型，检查：

- [ ] `selected_lmarena_model` 的值是否正确
- [ ] 如果正确，`human_approved` 是否已设为 `1`
- [ ] 如果无匹配，`selected_lmarena_model` 是否为 `-1`，`human_approved` 是否为 `1`
- [ ] JSON 格式是否正确（无语法错误）

### 4.5 特殊处理：artificial_analysis

**重要**：`artificial_analysis_review.json` 会应用到所有 10 个 benchmark：
- `aa_lcr`
- `aime_2025`
- `gpqa_diamond`
- `humanitys_last_exam`
- `ifbench`
- `live_code_bench`
- `mmlu_pro`
- `scicode`
- `tau_bench_telecom`
- `terminal_bench_hard`

**只需要审核这一个文件**，审核完成后，映射会自动应用到所有 10 个 benchmark。

## 步骤5：应用审核结果

### 5.1 脚本位置

**脚本**：`src/processing/apply_review_results_v2.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/apply_review_results_v2.py
```

### 5.2 处理逻辑

1. **读取审核文件**：从 `data/processed/entity_resolution/reviewed_files/` 读取所有 `*_review.json` 文件
2. **提取最终映射**：
   - 对于每个模型，读取 `selected_lmarena_model` 字段
   - 如果值为模型名称（字符串），则创建映射
   - 如果值为 `0` 或 `-1`，则跳过（不创建映射）
3. **更新映射表**：将映射写入 `config/mapping.json`
4. **特殊处理**：`artificial_analysis_review.json` 会应用到所有 10 个 benchmark

### 5.3 输出文件

**输出文件**：`config/mapping.json`

**文件格式**：
```json
{
  "GPT-5.2 (xhigh)": "gpt-5.2",
  "Gemini 3 Flash": "gemini-3-flash",
  "o3": "o3-2025-04-16",
  ...
}
```

### 5.4 注意事项

- 只有 `selected_lmarena_model` 为模型名称（字符串）的条目才会被添加到映射表
- `selected_lmarena_model` 为 `0` 或 `-1` 的条目会被跳过
- 未审核的模型（`human_approved: 0`）也会被处理，但建议先审核再应用

## 步骤6：生成 Cleaned 数据文件

### 6.1 脚本位置

**脚本**：`src/processing/generate_cleaned_data.py`

**执行命令**：
```bash
cd Human-SIG
python src/processing/generate_cleaned_data.py
```

### 6.2 处理逻辑

1. **遍历所有原始数据**：从 `data/raw/` 目录读取所有 `data.csv` 文件
2. **提取模型名称和分数**：
   - 从每个 CSV 文件中识别模型名称列（可能是 "Model", "model", "AI System", "model_name" 等）
   - 从每个 CSV 文件中识别分数列（根据 benchmark 类型自动识别，如 "Score", "Intelligence AA-LCR", "score_value", "Numerical_Result", "accuracy" 等）
   - **重要**：只提取在 `model_extraction` JSON 文件中存在的模型名称（确保一致性）
3. **处理分数格式**：
   - 移除 ± 误差部分（如 "1490 ±6" → 1490.0）
   - 处理百分比格式（如 "71%" → 71.0）
   - 处理小数格式（如 "0.945" → 0.945）
   - 转换为浮点数用于排名计算
4. **计算排名**：
   - 按分数从大到小排序
   - 同分并列：相同分数的模型获得相同排名
   - 下一个排名跳过并列数量（如分数 [99, 98, 98, 97] → 排名 [1, 2, 2, 4]）
5. **生成映射文件**：
   - 从对应的 `reviewed_files` JSON 文件中读取 `selected_lmarena_model` 字段
   - 只记录字符串类型的映射（排除 0 和 -1）
   - **去重补丁**：如果多个 benchmark 模型映射到同一个 LMArena 模型，只保留第一个映射（后续重复会被自动跳过）

### 6.3 输出文件

**输出目录**：`data/processed/cleaned/{benchmark_id}/`

**每个 benchmark 文件夹包含两个文件**：

#### 6.3.1 cleaned_data.csv

包含三列：
- `model_name`：模型名称（与 `model_extraction` 中的命名完全一致）
- `score`：分数（浮点数）
- `rank`：排名（整数，同分并列）

**示例**：
```csv
model_name,score,rank
GPT-5 (high),76.0,1
GPT-5.1 (high),75.0,2
Claude Opus 4.5,74.0,3
KAT-Coder-Pro V1,74.0,3
GPT-5.2 (xhigh),73.0,5
GPT-5 (medium),73.0,5
```

#### 6.3.2 mapping.json

包含该 benchmark 的模型名称到 LMArena 模型名称的映射。

**文件格式**：
```json
{
  "GPT-5.2 (xhigh)": "gpt-5.2",
  "Gemini 3 Flash": "gemini-3-flash",
  "o3": "o3-2025-04-16",
  "DeepSeek V3.2": "deepseek-v3.2",
  ...
}
```

**重要特性**：
- 只包含有效的映射（`selected_lmarena_model` 为字符串）
- 每个 LMArena 模型在该 benchmark 中最多出现一次（重复映射会被自动去除，只保留第一个）
- 模型名称与 `model_extraction` 中的命名完全一致

### 6.4 特殊处理

**Artificial Analysis**：
- 10 个 benchmark 共享同一个 `artificial_analysis_models.json` 和 `artificial_analysis_review.json`
- 但每个 benchmark 有独立的文件夹和 `cleaned_data.csv`（因为分数不同）
- 所有 benchmark 的 `mapping.json` 内容相同（来自同一个 `artificial_analysis_review.json`）

**LMArena Categories**：
- 7 个 category 共享同一个 `lmarena_models.json` 和 `lmarena_review.json`
- 每个 category 有独立的文件夹和 `cleaned_data.csv`（因为每个 category 的分数不同）
- 所有 category 的 `mapping.json` 内容相同（来自同一个 `lmarena_review.json`）

### 6.5 去重补丁说明

**问题**：在某些情况下，一个 benchmark 中可能有多个模型映射到同一个 LMArena 模型（例如 "o3" 和 "o3-pro" 都映射到 "o3-2025-04-16"）。

**解决方案**：
- 脚本会自动检测重复的 LMArena 映射
- 只保留第一个遇到的映射，后续重复会被自动跳过
- 会在控制台输出警告信息，显示发现了多少个重复映射

**注意**：在正确的映射表下不应该出现这种情况，但为了确保后续处理能够正常运行，这个补丁是必要的。

### 6.6 文件命名规则

**Benchmark ID 生成规则**：
- `data/raw/lmarena/Overall/data.csv` → `lmarena_overall`
- `data/raw/artificial_analysis/aa_lcr/data.csv` → `artificial_analysis_aa_lcr`
- `data/raw/selenium/humaneval/data.csv` → `selenium_humaneval`
- `data/raw/frontiermath/frontiermath_tier_1_3/data.csv` → `frontiermath_frontiermath_tier_1_3`

**输出路径**：
- `data/processed/cleaned/{benchmark_id}/cleaned_data.csv`
- `data/processed/cleaned/{benchmark_id}/mapping.json`

## 🔍 检测未审核的模型

### 自动检测（推荐）

运行 `apply_review_results_v2.py` 时，脚本会自动检测所有 benchmark 的未审核模型：

```bash
cd Human-SIG
python src/processing/apply_review_results_v2.py
```

**检测逻辑**：
- 从 `data/raw/` 或 `data/cleaned/` 目录读取所有 `data.csv` 文件
- 提取每个文件中的模型列表
- 检查这些模型是否在对应的审核文件中已审核
- **已审核标准**：`human_approved: 1` 且 `selected_lmarena_model` 不是 `0` 或 `-1`

**警告信息**：
如果检测到未审核的模型，系统会显示：
- ⚠️ 哪些 benchmark 有未审核的模型
- 每个 benchmark 的未审核模型列表（超过5个只显示前5个）
- 提示：未审核的模型在后续处理中会被丢弃

**处理方式**：
- 可以**忽略警告继续处理**：未审核的模型会被自动丢弃
- 如果需要保留这些模型：先审核它们，然后重新运行脚本

### 手动检测

如果需要单独检测某个文件或所有文件，可以使用检测脚本：

```bash
# 检测所有 benchmark
python src/processing/check_unreviewed_models.py

python src/processing/check_unreviewed_models.py data/raw/selenium/humaneval/data.csv
```

## 🎯 匹配规则总结

### ✅ 可以匹配的条件

1. **家族、子家族、版本号完全一致**
2. **参数量**：
   - 如果两个都有且一致 → 可以匹配
   - 如果只有一个有 → 可以匹配
   - 如果两个都没有 → 可以匹配

### ❌ 不能匹配的条件

1. **家族不一致**：如 GPT vs Gemini
2. **子家族不一致**：如 gpt-5 vs gpt-4
3. **版本号不一致**（标准化后）：如 5.1 vs 5.2
4. **参数量不一致**（如果两个都有）：如 32B vs 72B

### ⚠️ 不影响匹配的信息

- **日期**：不参与筛选
- **other_info**：不影响匹配

## ❓ 常见问题

### Q1: 如何知道哪些条目需要审核？

**A**: 搜索 `"needs_review": true` 或运行 `python src/processing/list_needs_review.py`

### Q2: `selected_lmarena_model` 为 `0` 是什么意思？

**A**: `0` 表示系统自动判断没有对应的 LMArena 模型。如果人类确认确实没有，应改为 `-1` 并设置 `human_approved: 1`

### Q3: `selected_lmarena_model` 为 `-1` 是什么意思？

**A**: `-1` 表示人类审核确认确实没有对应的 LMArena 模型（Score >= 1330）。这需要人工设置。

### Q4: 如何判断自动选择是否正确？

**A**: 检查 `selected_lmarena_model` 的值是否在 `candidates` 列表中，以及是否与 `benchmark_info` 的信息最匹配。

### Q5: artificial_analysis 的映射如何应用？

**A**: 审核 `artificial_analysis_review.json` 后，运行 `apply_review_results_v2.py`，脚本会自动将映射应用到所有 10 个 benchmark。

### Q6: 日期还影响匹配吗？

**A**: 不影响！日期筛选已经删除，不同格式的日期（如 dec 和 1201）不会影响匹配。

### Q7: other_info 中的信息影响匹配吗？

**A**: 不影响！other_info 只是参考信息，不影响匹配判断。但在自动选择多候选时，other_info 的相似度会被考虑。

### Q8: 如果检测到未审核的模型，必须审核吗？

**A**: 不是必须的。可以忽略警告继续处理，未审核的模型会被自动丢弃。如果需要保留这些模型，才需要先审核它们。

### Q9: 为什么有些模型显示为未审核？

**A**: 可能的原因：
- `human_approved: 0`（尚未被人类认可）
- `selected_lmarena_model: 0`（自动判断无匹配，但未确认）
- `needs_review: true`（有多个候选，需要人工确认）

### Q10: 如何让系统不检测未审核模型？

**A**: 修改 `apply_review_results_v2.py` 中的 `check_unreviewed` 参数为 `False`，或者直接使用 `load_review_file_json` 函数手动处理。

### Q11: cleaned_data.csv 中的模型名称必须和 model_extraction 一致吗？

**A**: 是的，必须完全一致。脚本会自动过滤，只保留在 `model_extraction` JSON 文件中存在的模型。

### Q12: 为什么 cleaned 目录下每个 benchmark 都有自己的 mapping.json？

**A**: 这是为了后续处理的便利。每个 benchmark 的映射文件：
- 只包含该 benchmark 中实际出现的模型
- 已经处理了重复映射（一个 LMArena 模型只对应一个 benchmark 模型）
- 可以直接用于该 benchmark 的数据处理，无需查找全局映射表

### Q13: 如果 cleaned_data.csv 中的模型在 mapping.json 中没有映射怎么办？

**A**: 这些模型在后续处理中会被跳过（无法映射到 LMArena Study Universe）。这是正常的，因为不是所有 benchmark 模型都能在 LMArena 中找到对应（Score >= 1330）。

### Q14: 去重补丁是如何工作的？

**A**: 当脚本发现多个 benchmark 模型映射到同一个 LMArena 模型时：
- 只保留第一个遇到的映射
- 后续重复映射会被自动跳过
- 会在控制台输出警告信息
- 这确保了每个 LMArena 模型在每个 benchmark 中最多出现一次
