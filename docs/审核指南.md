## 📖 JSON文件结构

每个JSON文件的格式如下：

```json
{
  "benchmark_model_name": {
    "benchmark_info": {
      "family": "gpt",
      "subfamily": "gpt-5",
      "version": "5",
      "date": null,
      "parameters": null,
      "other_info": null
    },
    "candidates": [
      {
        "lmarena_model": "gpt-5-high",
        "family": "gpt",
        "subfamily": "gpt-5",
        "version": "5",
        "date": null,
        "parameters": null,
        "other_info": ["high"]
      },
      {
        "lmarena_model": "gpt-5-chat",
        "family": "gpt",
        "subfamily": "gpt-5",
        "version": "5",
        ...
      }
    ]
  }
}
```

### 字段说明

- **benchmark_info**: Benchmark中模型的结构化信息
  - `family`: 家族（如 gpt, gemini, claude）
  - `subfamily`: 子家族（如 gpt-5, gemini-pro）
  - `version`: 版本号（已标准化：3和3.0视为相同）
  - `date`: 日期（不参与匹配判断）
  - `parameters`: 参数量（如果都有且不一致，则排除匹配）
  - `other_info`: 其他信息（不影响匹配）

- **candidates**: LMArena中可能匹配的模型列表
  - 如果只有一个候选：`[{"lmarena_model": "model-name", ...}]`
  - 如果未找到匹配：`[{"lmarena_model": "NO_MATCH_FOUND"}]`

## ✅ 审核步骤

### 步骤1：打开文件

使用以下工具之一打开JSON文件：
- **VS Code**（推荐）：自动格式化，语法高亮
- **Notepad++**：轻量级编辑器
- **在线JSON查看器**：如 https://jsonviewer.stack.hu/

### 步骤2：审核每个模型

对于每个benchmark模型（JSON文件中的每个key）：

#### 2.1 检查匹配信息

查看 `benchmark_info` 和 `candidates` 中的结构化信息：

**必须一致的信息**：
- ✅ **family**（家族）：必须完全一致
- ✅ **subfamily**（子家族）：必须完全一致（如果都有）
- ✅ **version**（版本号）：必须一致（已标准化：3=3.0）

**如果都有且不一致则排除**：
- ❌ **parameters**（参数量）：如果两个都有且不一致，不匹配

**不影响匹配**：
- ⚠️ **date**（日期）：不参与筛选
- ⚠️ **other_info**（其他信息）：不影响匹配

#### 2.2 选择正确的匹配

**情况1：有多个候选**
- 检查每个候选的 `family`, `subfamily`, `version` 是否与benchmark一致
- 选择最正确的候选
- **删除其他不正确的候选**（从candidates数组中删除）
- **只保留一个候选**

**情况2：只有一个候选**
- 检查该候选是否正确
- 如果正确，保留
- 如果不正确，可以：
  - 删除该候选，改为 `[{"lmarena_model": "NO_MATCH_FOUND"}]`
  - 或手动添加正确的候选

**情况3：未找到匹配（NO_MATCH_FOUND）**
- 检查是否真的没有匹配
- 如果确实没有，保留
- 如果有但算法未找到，手动添加候选

#### 2.3 保存修改

- 确保JSON格式有效（VS Code会自动检测）
- 保存文件（Ctrl+S）

## 🎯 匹配规则总结

### ✅ 可以匹配的条件

1. **家族、子家族、版本号完全一致**
2. **参数量**：
   - 如果两个都有且一致 → 可以匹配
   - 如果只有一个有 → 可以匹配
   - 如果两个都没有 → 可以匹配

### ❌ 不能匹配的条件

1. **家族不一致**：如 GPT vs Gemini
2. **子家族不一致**：如 gpt-5 vs gpt-4
3. **版本号不一致**（标准化后）：如 5.1 vs 5.2
4. **参数量不一致**（如果两个都有）：如 32B vs 72B

### ⚠️ 不影响匹配的信息

- **日期**：不参与筛选（已删除日期筛选）
- **other_info**：不影响匹配

## 🔍 检测未审核的模型

在应用审核结果之前，系统会自动检测是否有未审核的模型。这对于以下场景很有用：
- 用户替换了 `input.txt`，新增了一些模型
- 用户不想审核新模型，只想继续处理
- 需要快速了解哪些模型还未审核

### 自动检测（推荐）

运行 `apply_review_results_v2.py` 时，脚本会自动检测所有 benchmark 的未审核模型：

```bash
cd Human-SIG
python src/processing/apply_review_results_v2.py
```

**检测逻辑**：
- 从 `data/cleaned/` 目录读取所有 `data.csv` 文件
- 提取每个文件中的模型列表
- 检查这些模型是否在对应的审核文件中已审核
- **已审核标准**：模型在审核文件中存在，且 `candidates` 数组只有一个元素，且该元素的 `lmarena_model` 不是 `'NO_MATCH_FOUND'`

**警告信息**：
如果检测到未审核的模型，系统会显示：
- ⚠️ 哪些 benchmark 有未审核的模型
- 每个 benchmark 的未审核模型列表（超过5个只显示前5个）
- 提示：未审核的模型在后续处理中会被丢弃

**处理方式**：
- 可以**忽略警告继续处理**：未审核的模型会被自动丢弃
- 如果需要保留这些模型：先审核它们，然后重新运行脚本

### 手动检测

如果需要单独检测某个文件或所有文件，可以使用检测脚本：


### 检测结果说明

**已审核的模型**：
- ✅ 模型在审核文件中存在
- ✅ `candidates` 数组只有一个元素
- ✅ 该元素的 `lmarena_model` 不是 `'NO_MATCH_FOUND'`

**未审核的模型**（会被丢弃）：

## ❓ 常见问题

### Q1: 一个模型有多个候选，如何选择？

**A**: 选择家族、子家族、版本号完全一致，且参数量也一致的候选。如果不确定，选择最接近的匹配。

### Q2: 如何判断版本号是否一致？

**A**: 版本号已标准化，3和3.0视为相同。如果版本号不同（如 5.1 vs 5.2），则不一致。

### Q3: 参数量格式不同怎么办？

**A**: 参数量格式应该一致（如 32B vs 32B）。如果格式不同但数值相同（如 32B vs 32b），视为一致。如果数值不同（如 32B vs 72B），则不一致。

### Q4: artificial_analysis的映射如何应用？

**A**: 审核 `artificial_analysis_review.json` 后，运行 `apply_review_results_v2.py`，脚本会自动将映射应用到所有10个benchmark。

### Q5: 日期还影响匹配吗？

**A**: 不影响！日期筛选已经删除，不同格式的日期（如dec和1201）不会影响匹配。

### Q6: other_info中的信息影响匹配吗？

**A**: 不影响！other_info只是参考信息，不影响匹配判断。

### Q7: 如何知道哪些模型还未审核？

**A**: 运行 `apply_review_results_v2.py` 时会自动检测并显示未审核的模型。也可以单独运行 `check_unreviewed_models.py` 进行检测。

### Q8: 如果检测到未审核的模型，必须审核吗？

**A**: 不是必须的。可以忽略警告继续处理，未审核的模型会被自动丢弃。如果需要保留这些模型，才需要先审核它们。

### Q9: 为什么有些模型显示为未审核？

**A**: 可能的原因：
- 模型不在审核文件中（新模型）
- `candidates` 数组有多个元素（需要选择）
- 唯一的候选是 `'NO_MATCH_FOUND'`（未找到匹配）

### Q10: 如何让系统不检测未审核模型？

**A**: 修改 `apply_review_results_v2.py` 中的 `check_unreviewed` 参数为 `False`，或者直接使用 `load_review_file_json` 函数手动处理。
